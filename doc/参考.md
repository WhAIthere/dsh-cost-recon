# 搜索旁路账单 · 对接说明

> 给统计方的唯一要点：**原生 DeepSeek 搜索的 token 不在会话日志、也不在官方用量投影里**，只在这个文件里。读它，就能把这部分补进总账。

## 1. 数据在哪

| 项 | 值 |
|---|---|
| 文件 | `%USERPROFILE%\.dsh\search-usage.jsonl`（可用环境变量 `DSH_SEARCH_AUDIT_LOG` 覆盖） |
| 格式 | JSONL / UTF-8 / **只追加**，一行 = 一次搜索请求（= 一次 Anthropic 兼容 Messages 调用） |
| 写入者 | 插件 `dsh-search-audit`；它在宿主侧包了 `globalThis.fetch`，不改请求/响应，只读响应里的 `usage` |
| 时延 | 响应返回后立刻追加；文件可能正在被写 → 末行可能不完整 |

## 2. 一行的样子

```json
{"ts":1792409954836,"endpoint":"https://api.deepseek.com/anthropic/v1/messages",
 "sessionId":"session-6a18ee82-…","model":"deepseek-v4-flash","query":"…","maxUses":1,
 "ok":true,"status":200,
 "usage":{"inputTokens":8809,"outputTokens":1114,"cacheReadTokens":256,"cacheWriteTokens":0},
 "source":"dsh-search-audit"}
```

## 3. 字段

| 字段 | 说明 |
|---|---|
| `ts` | ms 时间戳（**响应时刻**，与计费时刻同量级） |
| `sessionId` | 发起搜索的会话；**可能为 `null`**（插件早期版本 / 无 initiator），这类行无法归属 |
| `model` | 实际调用的模型（目前 `deepseek-v4-flash`） |
| `usage.inputTokens` | **未命中（未缓存）输入**，与 DSH 语义一致 |
| `usage.cacheReadTokens` | 缓存命中输入 |
| `usage.outputTokens` | 输出 |
| `query` / `maxUses` / `ok` / `status` | 调试用，可不看 |
| `source` | `dsh-search-audit` = 实测；`estimate` = 人工补历史（`note` 里写依据，金额照算） |

## 4. 怎么读（Python，够用）

```python
import json, pathlib
from collections import defaultdict

rows = []
for line in (pathlib.Path.home()/".dsh"/"search-usage.jsonl").read_text(encoding="utf-8").splitlines():
    line = line.strip()
    if not line:
        continue
    try:
        rows.append(json.loads(line))
    except json.JSONDecodeError:
        continue                       # 末行可能正在写，跳过即可

agg = defaultdict(lambda: {"calls": 0, "inp": 0, "out": 0, "hit": 0})
for r in rows:
    u = r.get("usage") or {}
    a = agg[r.get("sessionId") or "(unknown)"]
    a["calls"] += 1
    a["inp"] += u.get("inputTokens") or 0
    a["out"] += u.get("outputTokens") or 0
    a["hit"] += u.get("cacheReadTokens") or 0
```

## 5. 归到会话 / 轮次

- **会话**：直接用 `sessionId`。
- **轮次**：记录里**没有 turn**。用 `ts` 落在哪一轮区间判断（`turn/start` 事件在会话日志里，取「起始时间 ≤ ts 的最后一轮」）。
- 更准的办法：调 Host 路由拿现成的每轮次数（见 §6 的 `calls`），它按会话事件里的 `web/deepseek-search-llm-request` 精确归属。

## 6. 另一条路：HTTP 路由（**仅浏览器内可用**）

```
GET /api/turn-cost/search-usage?from=<ms>&session=<id>
→ { "records": [...], "calls": [{"turn":1,"count":12}], "total": n, "returned": m }
```

- `records`：`ts >= from` 且 `sessionId === session` 的行；
- `calls`：该会话每轮的原生搜索次数（Host 读会话事件算的，权威）；
- ⚠️ 受 DSH 的 `/api` 信任栅栏保护，需要浏览器会话认证，**外部进程调用会 401**。统计项目请直接读文件（§1），别走这条路。

## 7. 计价

```
cost = inp×P_in + hit×P_cache + out×P_out     （单位：元，价格按「元/百万 token」）
```

`deepseek-flash`（北京时间，节假日另算）：

| 时段 | 未命中输入 | 缓存命中 | 输出 |
|---|---:|---:|---:|
| 空闲 | ¥1 / M | ¥0.02 / M | ¥4 / M |
| 高峰（工作日 09–12、14–18）×2 | ¥2 / M | ¥0.04 / M | ¥8 / M |

另有每次搜索 ¥0.005 的说法，但实测对账（18 次请求 ≈ token 部分 ¥0.44，官方差额 ¥0.4586）**对不上这笔费**，建议先按 0 计。

## 8. 已知边界

1. **只覆盖插件安装之后的搜索**（本机 2026-10-19 19:36 起）。更早的搜索没有任何记录，只能人工估算（见 `source:"estimate"`）。
2. **只覆盖原生引擎**（`deepseek-official`）。free-search 各引擎的调用是普通工具结果，token 已记在会话的 `assistant/message` 里，**不要重复统计**。
3. 一次调用可能包含「搜索 + 摘要 + 引用」，`usage` 是这一次调用的总量，不必拆分。
4. 官方小时桶**不含**这部分（这正是统计缺口的原因）；用本文件与官方桶相加才是总账。
5. 插件未运行时（例如桌面端没开）不会有新行——统计方看到「没有新数据」先确认进程在跑。
